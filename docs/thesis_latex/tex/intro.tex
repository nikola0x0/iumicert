\section{Motivation}

\subsection{Traditional Academic Credential Systems}
Traditional paper-based and PDF credentials suffer from fundamental issues. Centralized verification requires employers to contact institutions directly for each credential check, creating administrative overhead and delays in hiring processes. These credentials are easily forged, as paper certificates and digital PDFs lack cryptographic protection against tampering. Furthermore, traditional systems cannot verify individual achievements—only complete degrees or certificates can be validated, preventing granular verification of specific skills or courses.

\subsection{Existing Blockchain Credential Systems}
Blockchain-based credentials such as BlockCerts \cite{blockcerts_mit}, CVSS \cite{nguyen2018cvss}, IU-TransCert \cite{le_iutranscert}, and IU-VecCert \cite{nguyen2024iuvec} have emerged as solutions to address the limitations of traditional systems. These systems provide immutability and transparency through blockchain anchoring, enabling cryptographic verification without institutional contact. The tamper-proof nature of blockchain records ensures that once credentials are issued, they cannot be modified or forged, representing a significant advancement over paper-based systems.

\subsection{Remaining Technical Gaps in Current Blockchain Systems}
Despite these advances, existing blockchain credential systems still face critical limitations. First, they lack granularity—most systems can only verify whole certificates or transcripts, not individual courses or micro-credentials. Second, Merkle tree-based proof systems produce proofs that scale with tree depth (O(log n)), resulting in larger proof sizes for systems with many credentials. Third, current systems require full transcript disclosure for any verification, lacking selective disclosure mechanisms that would preserve student privacy. Fourth, temporal integrity is absent—there is no cryptographic binding to prove when credentials were issued, enabling potential backdating attacks. Finally, storing full credential hashes on-chain creates high costs that limit scalability for large-scale institutional deployments.

\subsection{Our Solution: Verkle Tree Technology}
Verkle trees, originally designed for Ethereum state proofs, address these gaps in blockchain credential systems. They provide compact proofs with constant size (approximately 1.8 KB) regardless of dataset size, solving the proof scaling problem. The technology enables granular verification where each course becomes an independent micro-credential that can be verified separately. Students gain selective disclosure capabilities—they can prove specific achievements without revealing their full academic records. The term-based tree structure with blockchain timestamps provides temporal binding, creating verifiable issuance timelines that prevent backdating. Finally, the architecture is cost-effective, requiring only 32-byte root commitments to be stored on-chain per academic term, enabling scalable deployment for institutions with thousands of students.

\section{Problem Statement}
How can we design a \textbf{blockchain-based system for verifiable academic credentials} using \textbf{Verkle tree technology} that addresses the limitations of existing solutions by:

\begin{enumerate}
    \item Enabling \textbf{granular verification} of individual courses (micro-credentials)
    \item Providing \textbf{compact cryptographic proofs} with constant-size guarantees
    \item Maintaining \textbf{temporal integrity}—proving when credentials were issued
    \item Supporting \textbf{selective disclosure}—revealing only relevant achievements
    \item Being \textbf{cost-effective} for large-scale deployment
\end{enumerate}

\section{Scope}
The scope of this thesis is defined with clear boundaries on what is included, what is excluded, and the fundamental assumptions and constraints that shape the system design and evaluation.

\subsection{In Scope}
This thesis encompasses the complete design, implementation, and evaluation of the IU-MiCert system for verifiable academic credentials. The work includes Verkle tree construction for academic records, where each course completion is treated as an independent micro-credential with its own cryptographic proof. Blockchain anchoring of term commitments is implemented through smart contract deployment on the Ethereum Sepolia testnet, providing immutable storage of cryptographic roots. Receipt generation with cryptographic proofs enables students to receive portable credentials that can be verified independently. The system supports both local verification (cryptographic proof validation) and on-chain verification (blockchain root queries). Web interfaces for all three stakeholder groups—issuers, students, and verifiers—are implemented to provide accessible interaction with the system. Finally, a credential revocation mechanism using version-based supersession is designed and implemented to handle cases of academic misconduct or grade corrections.

\subsection{Out of Scope}
While the system is designed with extensibility in mind, several areas are explicitly excluded from this thesis work. Real-time integration with Learning Management Systems is not implemented; instead, the system relies on manual data export and import procedures. The data format for LMS integration is defined and documented, but automated hooks and real-time synchronization are planned for future work. Mobile native applications are not developed; however, web-responsive design ensures the system is accessible on mobile devices through web browsers. Cross-institutional credential aggregation, where credentials from multiple universities are combined into a single verifiable record, is beyond the scope of this single-institution proof-of-concept. Similarly, multi-issuer federation systems that would enable trust relationships between multiple universities are not addressed in this work.

\subsection{System Assumptions}
The IU-MiCert system operates under several fundamental assumptions that define its operational context. First, we assume data availability: course completion data can be exported from the institution's Learning Management System in structured formats such as JSON or CSV. The system design accommodates standard LMS data export capabilities without requiring proprietary integrations. Second, we assume data quality and integrity: the institution provides accurate, finalized grade data per academic term. The system does not validate the correctness of grades themselves but rather provides mechanisms to verify that credentials, once issued, have not been tampered with. Third, network access is assumed: verifiers must have internet connectivity to query the Ethereum blockchain for term root validation. While the system caches blockchain data to minimize network dependency, initial verification requires blockchain access. Fourth, the trust model assumes a single issuer: the university is the trusted credential authority responsible for issuing valid credentials. The blockchain provides immutability and transparency, but the initial credential issuance requires trust in the institution. Finally, student consent is assumed: students agree to receive and manage digital receipts in JSON format and understand the implications of selective disclosure.

\subsection{System Constraints}
Several technical and operational constraints influence the system design and deployment. The manual data pipeline represents a significant constraint: the system requires manual export and conversion from LMS systems, as real-time hooks and automated synchronization are not implemented in this version. This manual process introduces potential delays between grade finalization and credential availability. Blockchain dependency is another constraint: verification requires access to the Ethereum network, specifically the Sepolia testnet in the current deployment. While this provides strong security guarantees, it also means verifiers must be able to query blockchain state, either directly or through cached data. The single institution design reflects the system's architecture: it is optimized for a single university issuing credentials, not for federated multi-institutional scenarios. This simplifies trust relationships and key management but limits immediate applicability to consortium use cases. Technical literacy requirements present a usability constraint: users need basic understanding of JSON file formats and blockchain concepts to effectively use the system. While web interfaces abstract much of this complexity, some technical familiarity enhances the user experience. Finally, gas costs represent an economic constraint: publishing term roots to the blockchain requires ETH for transaction fees. While costs are minimal (approximately 0.004 ETH per term), institutions must manage cryptocurrency wallets and maintain sufficient balances for root publication operations.

\section{Thesis Organization}
This thesis is organized into eight chapters that systematically present the research, design, implementation, and evaluation of the IU-MiCert system.

\textbf{Chapter 1: Introduction} establishes the research foundation by presenting the motivation for blockchain-based micro-credential systems, defining the specific problem addressed by this work, delineating the scope and constraints of the system, and outlining measurable research objectives.

\textbf{Chapter 2: Background and Related Work} provides the theoretical foundation and contextualizes the research within existing literature. This chapter first presents the theoretical background covering blockchain technology, Ethereum platform, Pedersen commitments, Inner Product Arguments (IPA), and Verkle trees. It then surveys current advancements in blockchain credential systems including BlockCerts, CVSS, EduCTX, and previous institutional projects (IU-TransCert, IU-VecCert). Finally, it identifies specific research gaps that IU-MiCert addresses.

\textbf{Chapter 3: Methodology} describes the system design and architectural approach. Beginning with high-level system requirements derived from the problem statement, this chapter presents functional and non-functional requirements, use case analyses, and comprehensive system architecture. The chapter details the design of Verkle tree construction, proof generation and verification mechanisms, blockchain integration strategy, credential revocation system, and complexity analysis.

\textbf{Chapter 4: Prototyping} justifies the technology stack and development tools selected for the implementation. This chapter explains the rationale for choosing Go for backend development, Next.js for frontend applications, and Solidity for smart contracts. It presents the complete development toolchain and describes the data pipeline design for processing academic records into verifiable credentials.

\textbf{Chapter 5: Implementation} provides technical details of the system implementation. This chapter presents algorithms for Verkle tree construction, proof generation, and verification using formal pseudocode notation. It documents the CLI tool implementation, smart contract code, revocation system implementation, web interface development, and integration testing strategy.

\textbf{Chapter 6: Results} presents the evaluation of the implemented system through performance benchmarks, security analysis, cost analysis, and comparison with existing solutions. This chapter includes detailed happy case scenarios demonstrating credential issuance, student verification with selective disclosure, and credential revocation workflows. Comprehensive analysis discusses performance achievements, usability evaluation, and validation of design goals.

\textbf{Chapter 7: Discussion} interprets the results in the context of the research objectives and broader academic credential landscape. This chapter analyzes the implications of performance and security findings, articulates the research contributions, acknowledges limitations of the current implementation, and outlines future research directions organized by timeframe.

\textbf{Chapter 8: Conclusion} synthesizes the research contributions and their impact. This chapter summarizes the six key contributions of the work, discusses both academic and practical impact of the research, and provides final remarks on the balance achieved between security, privacy, efficiency, cost, and usability in the IU-MiCert system.
